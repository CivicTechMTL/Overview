# GitHub 101

**English** · [Français](GITHUB-101.fr.md)

A plain-language guide for people who have never used GitHub.
You don't need to code or install anything — everything below works in your web browser.

## What is GitHub?

GitHub is a website where people store and work on shared projects together.
Think of it like a shared Google Drive with a built-in history: every change is
saved, you can see who changed what and why, and nothing gets lost.

Civic Tech Montréal uses GitHub to keep our projects, documentation and
organizing notes in the open, so anyone can read them and suggest improvements.

## Key terms

| Term | What it means |
|---|---|
| **Repository (repo)** | A project folder. It holds files and their full history. This page lives in the *Overview* repo. |
| **README** | The welcome page of a repo. It's shown automatically when you open the repo. |
| **Markdown (.md)** | The simple formatting used in most files here. `**bold**`, `# Heading`, `- list item`. |
| **Commit** | A saved change, with a short message explaining what changed. |
| **Branch** | A separate copy of the files where you can make changes without affecting the main version. The main version is called `main`. |
| **Fork** | Your own copy of someone else's repo, used when you don't have permission to edit it directly. GitHub makes one for you automatically. |
| **Pull request (PR)** | A request to add your changes to the main version. Others can review, comment and approve it before it's merged. |
| **Merge** | Combining approved changes into `main`. |
| **Issue** | A to-do, question, idea or bug report. Anyone can open one to start a conversation. |
| **Review** | When someone reads a pull request and approves it or suggests changes. |
| **Organization** | A group account that owns several repos. Ours is [CivicTechMTL](https://github.com/CivicTechMTL). |

## Your first contribution, step by step

### Step 1: Create an account
Go to [github.com/signup](https://github.com/signup) and create a free account.

### Step 2: Open an issue (ask, suggest or report)
1. Go to the repo you're interested in (for example, this one).
2. Click the **Issues** tab, then **New issue**.
3. Give it a clear title and describe your idea or question.
4. Click **Submit new issue**. Someone from the team will reply.

### Step 3: Suggest a change to a file
1. Open the file you want to change.
2. Click the ✏️ (pencil) icon in the top right of the file.
   If you don't have edit access, GitHub will make a fork for you — that's normal.
3. Make your edits. Use the **Preview** tab to check how it looks.
4. Click **Commit changes…** and write a short message (e.g. "Fix broken Slack link").
5. Choose **Create a new branch** (or **Propose changes** if you're on a fork).

### Step 4: Open a pull request
1. GitHub will show a **Create pull request** button — click it.
2. Explain what you changed and why. If it relates to an issue, write
   `Closes #12` (using the issue number) so they're linked.
3. Click **Create pull request**.

### Step 5: Respond to feedback
A reviewer may comment or ask for changes. You can keep editing the same branch —
your pull request updates automatically. Once it's approved, it gets merged. 🎉
